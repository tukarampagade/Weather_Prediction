01

Project Summary

This project implements a complete, end-to-end binary classification system that predicts whether it will rain tomorrow, based on today's atmospheric readings — temperature, humidity, pressure, wind speed and cloud cover. Raw readings are cleaned, engineered into additional features, and standardized before being passed through a feed-forward neural network with a ReLU hidden layer and a Sigmoid output layer, trained with Binary Cross-Entropy loss and the Adam optimizer.

The trained network is evaluated with Accuracy, Precision, Recall and F1 Score on a held-out test set, then served live through a Flask web application so a real request can be scaled, classified, and returned as a rain probability in real time.

The neural network — including both optimizers (SGD and Adam) and every loss function — is implemented entirely from scratch using NumPy. No TensorFlow, Keras or PyTorch is used anywhere in this codebase, keeping every matrix operation, gradient and weight update fully transparent for academic evaluation.

04

Viva Questions

Twenty viva-ready questions covering every concept an examiner is likely to probe.

Gradient descent is an iterative optimization algorithm that updates each weight in the direction opposite to the gradient of the loss function, taking small steps controlled by a learning rate until the loss stops improving. It is used because it scales to the thousands of parameters in a neural network, where an exact analytical solution is not practical.

Backpropagation computes how much each weight contributed to the final error by propagating the loss gradient backward through the network, layer by layer, using the chain rule. It turns a single forward-pass error into a precise gradient for every weight and bias in the model.

The network is a composition of functions — linear layers followed by activations — so the effect of an early weight on the final loss passes through every layer after it. The chain rule is the calculus rule for differentiating composed functions, letting the gradient be built layer by layer instead of derived from scratch for the whole network at once.

In deep networks using Sigmoid or Tanh, the derivative of these functions is small almost everywhere and shrinks toward zero at the extremes. When gradients are multiplied together across many layers during backpropagation, they can shrink exponentially, so early layers receive almost no learning signal and train very slowly.

ReLU outputs the input directly when it is positive and zero otherwise, so its gradient is either 1 or 0 — it never shrinks the way Sigmoid's gradient does. This keeps gradients flowing through the hidden layers during backpropagation, which is why ReLU is used in this project's hidden layer.

Sigmoid squashes any real number into the range (0, 1), which is exactly the range a probability must fall in. It is used at the output layer so the network's raw score can be read directly as a probability of rain.

Binary Cross-Entropy directly measures the distance between a predicted probability and a 0/1 label in a way that penalizes confident wrong answers heavily. That steep penalty produces a strong, useful gradient exactly when the model most needs to correct itself.

Cross-Entropy Loss produces a much steeper gradient when the predicted probability is far from the true label, so the model learns faster for classification tasks. MSE combined with Sigmoid can flatten out when predictions are confidently wrong, slowing convergence — a problem Cross-Entropy avoids.

Adam keeps a per-parameter moving average of the gradient (momentum) and of the squared gradient (scale), then uses both to adapt the effective learning rate for every parameter individually. Plain SGD instead applies one fixed learning rate to every parameter, which converges less smoothly on uneven loss surfaces.

beta1 (typically 0.9) controls how quickly the first-moment estimate — the running average of the gradient — decays. beta2 (typically 0.999) controls how quickly the second-moment estimate — the running average of the squared gradient — decays.

epsilon is a tiny constant, typically 1e-8, added to the denominator of the Adam update rule purely to prevent division by zero when the second-moment estimate is close to zero.

He initialization scales the initial weights by the square root of 2 divided by the number of inputs to a layer. That factor of 2 compensates for ReLU zeroing out roughly half of its inputs, keeping the variance of activations stable as they pass through hidden layers.

Xavier initialization scales weights by the square root of 1 divided by the number of inputs, which suits the symmetric, saturating shape of Sigmoid and Tanh better than He initialization does. It is used at this project's output layer, where Sigmoid is the activation function.

Standardization subtracts the mean and divides by the standard deviation, putting every feature on a comparable scale. Without it, a feature with a naturally large range, such as pressure around 1000, would dominate gradient updates over a feature with a small range, such as cloud cover from 0 to 100.

np.clip() is used for numerical stability. Inside Sigmoid it keeps the input within a safe range so np.exp() cannot overflow; inside Cross-Entropy it keeps predicted probabilities away from exactly 0 or 1 so np.log() never receives zero, which would otherwise produce -infinity or NaN and break training.

Precision is the fraction of predicted-rain days that were actually rain, measuring how trustworthy a positive prediction is. Recall is the fraction of actual rain days the model successfully caught, measuring how complete the detection is.

F1 is the harmonic mean of Precision and Recall, so it only stays high when both are reasonably high — a model cannot inflate F1 by favoring one at the extreme expense of the other. That makes it a more honest single-number summary than accuracy alone on a dataset where rain and no-rain days are not perfectly balanced.

Implementing every matrix multiplication, activation, loss and gradient update in plain NumPy — with no TensorFlow, Keras or PyTorch — makes each step transparent and explainable rather than hidden inside a framework. That transparency is exactly what a viva examiner can ask about line by line.

Forward propagation is the process of passing an input through the network's layers in order — multiplying by weights, adding a bias, and applying an activation function at each layer — to produce a final output, which in this project is a probability of rain.

At server startup, app.py loads the saved weights, the fitted scaler and the training metrics once into memory. Each request to /predict then reuses that already-loaded model to scale the incoming form values and run a single forward pass, returning the result on the same page.

Setup Guide

Run the full project locally in PyCharm on Windows.

  1. 1

    Open the project in PyCharm

    Open the Weather_Prediction folder as a new project in PyCharm.

  2. 2

    Open the PyCharm terminal

    View → Tool Windows → Terminal.

  3. 3

    Create a virtual environment

    python -m venv venv
  4. 4

    Activate the virtual environment

    venv\Scripts\activate
  5. 5

    Install dependencies

    pip install -r requirements.txt
  6. 6

    Run preprocessing (optional console report)

    python preprocess.py
  7. 7

    Train the model and generate graphs

    python train_model.py
  8. 8

    Launch the web application

    python app.py
  9. 9

    Open the dashboard

    http://127.0.0.1:5000/
